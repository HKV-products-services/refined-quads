Use the mesh in D-HYDRO

WarningDo not call it mesh next to D-HyDAMO

D-HyDAMO scripts usually import from hydrolib.dhydamo.geometry import mesh (the module with mesh2d_clip, links1d2d_add_links_1d_to_2d and so on). mesh = generate(...) replaces that module, and the next mesh.<function>(...) fails with an AttributeError. Use another name, such as quad_mesh in the examples here.

Write a net file

from refined_quads import write_ugrid

write_ugrid(quad_mesh, workdir / "mesh_net.nc")

The file is UGRID-1.0 with the structure of the D-HYDRO mesh generator export: the Mesh2d topology with nodes, edges and faces, edge and face coordinates and face bounds. For EPSG:28992 the CRS variable has exactly the attributes of the D-Flow FM plugin; for another projected CRS they are derived with pyproj; a mesh without CRS gets no CRS variable.

variables: projected_coordinate_system, Mesh2d, Mesh2d_node_x, Mesh2d_node_y, Mesh2d_face_nodes, Mesh2d_edge_nodes, Mesh2d_edge_x, Mesh2d_edge_y, Mesh2d_face_x, Mesh2d_face_y, Mesh2d_face_x_bnd, Mesh2d_face_y_bnd
CRS: Amersfoort / RD New (EPSG 28992)

Bed levels

The net file has no bed level. Give it per cell in the model (mesh2d_face_z, bedLevType = 1), on the cells of one last MeshKernel rebuild after all changes to the mesh, and change nothing afterwards.

The D-HYDRO GUI builds the cells again from nodes and edges. A level per cell only fits when the net file holds exactly those cells, in that order.

NoteWhat MeshKernel does with the cells

MeshKernel keeps nodes and edges and finds the cells again each time it builds them. A small hole (at most six nodes) then becomes a cell, and a cell a clip removed can come back. A ring of more than six nodes is no cell after the rebuild. The model therefore holds the cells of the last rebuild, which can differ from the mesh refined-quads made.

With D-HyDAMO

from pathlib import Path

import refined_quads
from hydrolib.dhydamo.geometry import mesh

quad_mesh = refined_quads.generate(
    domain,
    cell_size=32.0,
    refinement_areas=refinement_areas,
    transition_rows=1,
    water_areas=water_areas,
    crs="EPSG:28992",
)
net_file = Path(output_path) / "refined_quads_net.nc"
refined_quads.write_ugrid(quad_mesh, net_file)

network = fm.geometry.netfile.network
mesh.mesh2d_from_netcdf(network, net_file)

# Other changes to the mesh (clips) go here, never later.

# The last MeshKernel rebuild
m2d = network._mesh2d
built = m2d.get_mesh2d()
m2d._set_mesh2d(node_x=built.node_x, node_y=built.node_y, edge_nodes=built.edge_nodes)

mesh.mesh2d_altitude_from_raster(network, rasterpath, "face", "mean", fill_option="nearest")
fm.geometry.bedlevtype = 1

1D2D links do not change the cells. A cell a clip removes after the last rebuild leaves a hole that the GUI fills, and the net file then has one cell too few.

Before opening the model, read the saved net file again. The cells must be the same, in the same order:

import netCDF4
import numpy as np
from hydrolib.core.dflowfm.net.models import Network
from hydrolib.core.dflowfm.net.reader import UgridReader

net = Path(output_path) / "dflowfm" / "network.nc"
with netCDF4.Dataset(net) as ds:
    face_x, face_y = ds["mesh2d_face_x"][:], ds["mesh2d_face_y"][:]
rebuilt = Network()
UgridReader(net).read_mesh2d(rebuilt._mesh2d)
assert len(rebuilt._mesh2d.mesh2d_face_x) == len(face_x), "other cells"
assert np.allclose(rebuilt._mesh2d.mesh2d_face_x, face_x), "other order"
assert np.allclose(rebuilt._mesh2d.mesh2d_face_y, face_y), "other order"

Bed level on the nodes

For bedLevType 3 to 6, sample the raster on the nodes after the last rebuild:

import types

# pandas 3 returns read-only arrays, which hydrolib fills in place: use writable copies
_stats = mesh.rasterstats.raster_stats_fine_cells
if not getattr(_stats, "_writable", False):
    def _writable_stats(*args, **kwargs):
        df = _stats(*args, **kwargs)
        return {c: types.SimpleNamespace(values=df[c].to_numpy(copy=True)) for c in df.columns}
    _writable_stats._writable = True
    mesh.rasterstats.raster_stats_fine_cells = _writable_stats

mesh.mesh2d_altitude_from_raster(network, rasterpath, "node", "mean", fill_option="nearest")
fm.geometry.bedlevtype = 3  # 3 mean, 4 minimum, 5 maximum of the node values

Which bedLevType

In the net file a “face” is a cell. In the MDU, “at face” means at a cell side (a flow link). The table uses cell, cell side and node.

bedLevType Input Level of a cell side Bed level of the cell
1 per cell: mesh2d_face_z the higher of the two cells its own value
2 per cell side: samples the sample
3 per node: mesh2d_node_z mean of its two nodes lowest of its cell sides
4 per node lower of its two nodes lowest of its cell sides, so its lowest node
5 per node higher of its two nodes lowest of its cell sides
6 per node mean of its nodes

Only cell sides shared with another cell count.

TipGeoTIFF fields in the D-HYDRO GUI

The GUI only reads rasters with the extension .tif (or .asc); with .tiff it hangs at “reading spatial operations”.

Read a net file

read_ugrid reads only the 2D mesh of a net file; a 1D network and other variables in it are ignored. The lattice is derived from the square cells, so you can check or refine a mesh from any program:

from refined_quads import check, read_ugrid

quad_mesh = read_ugrid(workdir / "mesh_net.nc")
print(check(quad_mesh).summary())

If the orthogonality repair does not close

D-Flow FM rejects a network whose edges are not orthogonal enough. The generator repairs such edges; if that does not close, generate raises OrthogonalityRepairError with the raw mesh (exc.mesh) and the problem locations (exc.bad_points), and the command line writes <output>_raw.nc and <output>_problems.gpkg next to the output so you can look at them in QGIS.
